# Indeed Job Scraper with Flask API

A Scrapy-based Indeed job scraper wrapped in a small Flask REST API. Send a keyword and a location to the API, it scrapes matching Indeed listings, stores the results as JSON in MySQL, and lets you fetch them back by job ID.

## What it does

1. `POST /jobcreate` with a `keyword` and `location`.
2. The API creates a row in a MySQL `jobs` table and launches a Scrapy spider in a separate process.
3. The spider searches Indeed, paginates through result pages (10 jobs per page, capped at about 50 results), and opens each job page.
4. For each job it extracts the fields below and writes them to `data/<job_id>.json`.
5. The JSON is saved into the job's `json_data` column, and the job is marked `completed`.
6. `POST /jobget` with a `jobid` returns the job's status and scraped data.

Requests to Indeed go through the [ScrapeOps](https://scrapeops.io) proxy to get around blocking.

### Scraped fields

| Field | Description |
|---|---|
| `position` | Rank within the search results page |
| `jobkey` | Indeed's unique job ID |
| `company` | Employer name |
| `jobDescription` | Sanitized job description (HTML) |
| `salary` | Salary range, when listed |
| `benefits` | List of benefits |
| `location` | Job location(s) |
| `jobType` | Full-time, part-time, etc. |

## Requirements

- Python 3.8+
- MySQL running locally
- A [ScrapeOps](https://scrapeops.io) API key (free tier works, limited to 1 concurrent request)

## Setup

```bash
git clone https://github.com/buildwithmueez/Indeed-Python-Scrape-with-Flask-API-Integration.git
cd Indeed-Python-Scrape-with-Flask-API-Integration/flask

python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

Note: `flask/requirements.txt` is UTF-16 encoded. If pip complains, re-save it as UTF-8 first.

### Database

Create the database (default connection is `mysql://root@localhost:3306/flask_scrapper_jobs`, set in `flask/api.py`):

```sql
CREATE DATABASE flask_scrapper_jobs;
```

Then create the tables from the repo root:

```bash
export FLASK_APP=flask/api.py       # Windows PowerShell: $env:FLASK_APP = '.\flask\api.py'
flask db upgrade
```

### ScrapeOps key

Add your own ScrapeOps API key to the spider and settings (see the security note below, and ideally load it from an environment variable instead of hardcoding it).

## Running

```bash
cd flask
python api.py
```

The API starts on `http://127.0.0.1:5000`.

## API

### `POST /jobcreate`

Starts a scrape and waits for it to finish.

```bash
curl -X POST http://127.0.0.1:5000/jobcreate \
  -H "Content-Type: application/json" \
  -d '{"keyword": "python developer", "location": "New York"}'
```

`keyword` defaults to `software engineer` and `location` to `California`.

```json
{
  "status": "success",
  "job_id": 1,
  "message": "Scraping job data for keyword: python developer in location: New York started. Job entry added to the database."
}
```

### `POST /jobget`

```bash
curl -X POST http://127.0.0.1:5000/jobget \
  -H "Content-Type: application/json" \
  -d '{"jobid": 1}'
```

```json
{
  "status": "success",
  "job_details": {
    "id": 1,
    "keyword": "python developer",
    "location": "New York",
    "status": "completed",
    "json_data": [ { "jobkey": ["..."], "salary": ["..."], "benefits": ["..."] } ]
  }
}
```

Job statuses: `started`, `completed`, `failed`.

## Running the spider without Flask

```bash
cd indeed_python_scrapy_scraper
scrapy crawl indeed_jobs -o output.json -a keyword="C++" -a location="New York"
```

## Known limitations

- `/jobcreate` is synchronous. The request blocks until the scrape finishes, so long scrapes can time out. A task queue (Celery/RQ) would fix this.
- Results are capped at about 50 jobs per search.
- Scrapy's Twisted reactor can't be restarted, so each crawl runs in its own subprocess.
- CSS class selectors (e.g. `css-775knl`) are auto-generated by Indeed and break regularly. Some fields (`jobTitle`, `salary` vs `jobType`) may be empty or overlap in the sample output.
- `flask/pipeline.py` is a leftover from a tutorial (quotes schema) and isn't wired in.
- Database credentials are hardcoded (`root`, no password) for local development only.
